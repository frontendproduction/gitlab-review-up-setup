# Ресурсы, управляемые вручную

## DNS-записи
Днс записи сейчас управляются через УИ облака, в дальнейшем их так же можно перенести в тераформ, если потребуется
Сейчас записи, за исключением секретов - такие:
```
@               SOA     3600    ns1.yandexcloud.net. mx.cloud.yandex.net. 1 10800 900 604800 900
@               NS      3600    ns1.yandexcloud.net.
                                ns2.yandexcloud.net.
@               A       300     51.250.33.16 # ip ВМ-ки с траефиком
*               CNAME   600     wefp.ru # чтобы поддомены резолвились траефиком
mail._domainkey TXT     21600   "v=DKIM; k=rsa; ..." # копируется из ЛК Яндекс 360
@               TXT     21600   "v=spf1 redirect=_spf.yandex.net" # копируется из ЛК Яндекс 360
@               MX      21600   10 mx.yandex.net
```

### Публичный ip
Сейчас 51.250.33.16

### Бакет для стейта терраформа
wefp-tf-backend, холодное, шифрованное

### Сервисный аккаунт 
wefp-sa

# Ресурсы, управляемые скриптами
В папке terraform - конфиг облака

Для инициализации тераформа  требуется заполнить переменные (ключ для этого нужен СТАТИЧЕСКИЙ, текущий статический ключ, 
хранится в секрете в локбоксе) а затем выпонить  `terraform_init_with_keys.sh`

!!! Коммитить заполненный `terraform_init_with_keys.sh` не надо, init делается 1 раз, для начала работы

Это описано в https://yandex.cloud/ru/docs/tutorials/infrastructure-management/terraform-state-storage#set-up-backend

Так же для работы яндекс провайдера необходимо задать `export TF_VAR_service_account_key_file="/path/to/key.json"`
с путем к файлу авторизованного ключа который надо скачать сеье на машину, он есть в облаке в секрете "авторизованный ключ"

В папке ansible - скрипты котрые сетапят ВМ-ки после создания их тераформом. Запустить скрипт (он же плейбук):
`ansible-playbook playbook.yaml`
